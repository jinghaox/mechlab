## NumPy: think in arrays, not loops

A NumPy array holds many numbers of the same type, and arithmetic on it applies to every element at once:

```python
import numpy as np

t = np.linspace(0, 1, 5)      # [0, 0.25, 0.5, 0.75, 1]
y = 3 * np.sin(2 * np.pi * t)  # no loop needed
```

This is called **vectorization**. It is shorter than a `for` loop and typically 10 to 100 times faster, because the loop runs in compiled code.

Matrices are 2-D arrays. Two operators are easy to confuse:

```python
A = np.array([[1, 2],
              [3, 4]])
x = np.array([1, 0])

A * A    # element-wise product: [[1, 4], [9, 16]]
A @ A    # matrix product:       [[7, 10], [15, 22]]
A @ x    # matrix times vector:  [1, 3]
```

In robotics almost every `*` between two matrices is a bug. Use `@`.

A few functions you will meet again and again: `np.linalg.solve(A, b)` solves $Ax = b$, `np.linalg.inv`, `np.linalg.eig` for eigenvalues, `np.cross` and `np.dot` for vectors, and `A.T` for the transpose.

## SciPy: let the computer solve the differential equation

Dynamic systems are described by differential equations of the form

$$\dot{x} = f(t, x)$$

where $x$ is the **state** and $\dot{x}$ is its time derivative. You write $f$ as a Python function and `solve_ivp` integrates it forward in time:

```python
from scipy.integrate import solve_ivp

def f(t, x):
    return -2.0 * x          # dx/dt = -2x

sol = solve_ivp(f, (0, 3), y0=[1.0], t_eval=np.linspace(0, 3, 100))
# sol.t holds the times, sol.y[0] holds x(t)
```

The exact answer here is $x(t) = e^{-2t}$, and the numerical result agrees to several digits. For most systems in this course no exact answer exists, and numerical integration is the only way to see what the system does. Lesson 1.3 looks inside the integrator.

## Matplotlib: always look at the result

```python
import matplotlib.pyplot as plt

plt.plot(sol.t, sol.y[0], label="x(t)")
plt.xlabel("time [s]")
plt.ylabel("x")
plt.legend()
plt.grid(True)
plt.show()
```

Make it a habit to label axes with units. When a simulation looks wrong, a plot with units is usually how you find out why.

## python-control: systems as objects

This library represents a dynamic system as an object you can analyze. A preview of what Module 1 and 2 will explain properly:

```python
import control as ct

G = ct.tf([1], [0.5, 1])            # G(s) = 1 / (0.5 s + 1)
t, y = ct.step_response(G)          # response to a unit step input
```

`ct.tf([1], [0.5, 1])` builds a **transfer function** from the coefficients of its numerator and denominator polynomials. Do not worry about what $s$ means yet. For now, treat `G` as "a system whose output approaches its input with a time constant of 0.5 s".

**Goal:** simulate the step response of an RC low-pass filter three ways and confirm they agree.

A resistor $R$ and a capacitor $C$ in series, driven by a voltage $u$, with the output $y$ taken across the capacitor, obey

$$\tau \, \dot{y} + y = u, \qquad \tau = RC$$

For a unit step input the exact solution is $y(t) = 1 - e^{-t/\tau}$.

@lab m0/first_order.py

With $R = 10\ \text{k}\Omega$ and $C = 100\ \mu\text{F}$ the script prints $\tau = 1$ s and $y(\tau) = 0.6321$, and the three curves lie on top of each other.

**Try these:**

1. Change `R` to `47e3`. Predict $\tau$ and the time to reach 63% before you run it.
2. How many time constants does it take to get within 1% of the final value? Read it off the plot, then derive it from the formula.
3. Loosen the solver tolerances to `rtol=1e-2, atol=1e-2`. How large does the error become, and where is it largest?
4. Replace the step with a sine: inside `rc`, set `u = np.sin(2 * np.pi * 1.0 * t)`, and remove the two comparison curves. What happens to the output amplitude as you raise the frequency? You have just measured why this circuit is called a low-pass filter.
