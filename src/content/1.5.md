A transfer function relates one input to one output and hides everything in between. Robots have many inputs and many outputs, and what happens inside matters. **State space** is the description that scales: a set of first-order equations, written compactly with matrices. It is the form MuJoCo uses internally, the form simulators integrate, and the starting point for the modern control methods of Module 8.

## What "state" means

The **state** of a system is the smallest set of numbers that, together with the future inputs, completely determines the future. If you know the state now, you need nothing else about the past.

For a mass on a spring, position alone is not enough: two masses at the same position can be moving in opposite directions. Position **and** velocity are enough. So the state has two entries.

A reliable rule of thumb: there is one state variable for each independent **energy store**. A mass stores kinetic energy (state: velocity). A spring stores potential energy (state: position). A capacitor stores energy in its voltage and an inductor in its current. The number of states is the **order** of the system, the same "order" as in first-order and second-order.

## Building the model

Take the mass-spring-damper $m\ddot{x} + c\dot{x} + kx = F$. Call the position $x_1$ and the velocity $x_2$. Then write the derivative of each state in terms of the states and the input:

$$\begin{aligned} \dot{x}_1 &= x_2 \\ \dot{x}_2 &= -\frac{k}{m}x_1 - \frac{c}{m}x_2 + \frac{1}{m}F \end{aligned}$$

The first line is just the definition of velocity. The second is Newton's law solved for the acceleration. One second-order equation has become two first-order ones. Stack them in matrix form:

$$\begin{bmatrix}\dot{x}_1 \\ \dot{x}_2\end{bmatrix} = \begin{bmatrix} 0 & 1 \\ -k/m & -c/m \end{bmatrix}\begin{bmatrix}x_1 \\ x_2\end{bmatrix} + \begin{bmatrix} 0 \\ 1/m \end{bmatrix} F$$

## The standard form

Every linear system can be written as

$$\dot{x} = Ax + Bu \qquad\qquad y = Cx + Du$$

| Symbol | Name | Role |
|---|---|---|
| $x$ | state vector | what the system "remembers" |
| $u$ | input vector | what you command |
| $y$ | output vector | what you measure |
| $A$ | system matrix | how the state evolves on its own |
| $B$ | input matrix | how inputs push on the state |
| $C$ | output matrix | which combination of states you see |
| $D$ | feedthrough matrix | direct path from input to output; usually zero |

The first equation is the dynamics. The second is the sensor. If an encoder measures position only, $C = \begin{bmatrix}1 & 0\end{bmatrix}$. Measure velocity instead and $C = \begin{bmatrix}0 & 1\end{bmatrix}$; the dynamics are unchanged. Keeping "how the system moves" apart from "what you can observe" is one of the main advantages of this form, and it becomes essential in state estimation.

## A second example: a DC motor with its electrical side

In lesson 1.1 the motor was first-order because the electrical dynamics were ignored. Include the winding inductance $L$ and there are two energy stores, inductor and rotor, so two states: current $i$ and speed $\omega$.

$$\begin{aligned} L\,\dot{i} &= -R\,i - K_e\,\omega + V \\ J\,\dot{\omega} &= K_t\,i - b\,\omega \end{aligned}$$

The first line is Kirchhoff's voltage law: the applied voltage is shared between the resistance, the inductance and the back-EMF $K_e\omega$. The second is Newton's law with motor torque $K_t i$. In matrix form:

$$\begin{bmatrix}\dot{i} \\ \dot{\omega}\end{bmatrix} = \begin{bmatrix} -R/L & -K_e/L \\ K_t/J & -b/J \end{bmatrix}\begin{bmatrix}i \\ \omega\end{bmatrix} + \begin{bmatrix} 1/L \\ 0 \end{bmatrix} V$$

The off-diagonal entries of $A$ show the coupling: speed affects current through back-EMF, and current affects speed through torque. You can read the physics straight from the matrix. Module 5 studies this model in detail.

## Connection to transfer functions

The two descriptions contain the same information about input-output behaviour. Applying $d/dt \to s$ to the state equations gives

$$G(s) = C\,(sI - A)^{-1}B + D$$

The denominator of that expression is $\det(sI - A)$, so:

> The **poles** of the transfer function are the **eigenvalues** of $A$.

Eigenvalues are characteristic numbers of a matrix; bridge lesson B4 explains them properly. For now the practical fact is enough: `np.linalg.eigvals(A)` gives you the poles, and so stability can be checked directly from $A$. The system is stable when every eigenvalue has a negative real part.

One caution: the state-space form of a system is **not unique**. You could use different state variables, such as position in millimetres or the sum and difference of two quantities, and get different matrices that describe the same system with the same poles.

## Why bother?

- **Many inputs and outputs.** $u$ and $y$ are vectors. A six-joint arm is one equation, not thirty-six transfer functions.
- **Simulation.** $\dot{x} = Ax + Bu$ is already in the form $\dot{x} = f(x)$ that integrators need.
- **Initial conditions** are built in: they are simply $x(0)$.
- **It generalizes.** A nonlinear system is $\dot{x} = f(x, u)$ with the same notion of state. In MuJoCo the state is exactly (`qpos`, `qvel`).

WPILib's state-space classes use these same four matrices. `LinearSystemId.createElevatorSystem(...)` returns a `LinearSystem` whose state is (position, velocity), whose input is voltage and whose output is position, with $A$ and $B$ computed from the motor constants, mass, drum radius and gearing. === summary ===

- The state is the minimal information that determines the future; one state per independent energy store.
- $\dot{x} = Ax + Bu$, $\ y = Cx + Du$.
- Mass-spring-damper: $x = \begin{bmatrix}\text{position} \\ \text{velocity}\end{bmatrix}$, $A = \begin{bmatrix} 0 & 1 \\ -k/m & -c/m \end{bmatrix}$, $B = \begin{bmatrix} 0 \\ 1/m \end{bmatrix}$.
- $G(s) = C(sI - A)^{-1}B + D$; the poles are the eigenvalues of $A$.
- The representation is not unique, but the poles are.
